## 1. Executive Summary

This proposal presents Rebaden, a web-based Security Information and Event Management (SIEM) platform designed for small to medium enterprise (SME) environments. The platform consolidates log ingestion, event correlation, alert management, and security investigation workflows into a unified, accessible interface. Rebaden addresses the shortage of affordable, deployable SIEM solutions for organizations that lack the resource overhead of commercial alternatives such as Splunk or IBM QRadar.

---

## 2. Problem Statement

Modern organizations face an ever-increasing volume of security events generated by servers, applications, firewalls, and user devices. Without a centralized system for collection, parsing, and analysis, security teams are vulnerable to:

- **Alert fatigue** from unfiltered log noise
- **Delayed incident response** due to fragmented tooling
- **Invisible attack patterns** that only emerge from correlating events across sources
- **Compliance gaps** stemming from inadequate audit trails

Existing SIEM solutions are either prohibitively expensive (Splunk, ArcSight), overly complex for lean teams (Elastic SIEM), or require significant infrastructure investment (Wazuh with Elastic Stack). Rebaden is designed to fill this gap with a lightweight, self-hosted, Django-based alternative that is deployable by a single engineer.

## 4. Scope

### In Scope
- Log file upload and parsing (Apache Common/Combined, syslog, JSON formats)
- Automated event classification and severity assignment
- Alert lifecycle management (open → in-progress → resolved)
- Investigation/case creation with checklist-based recommended actions
- Dashboard with event counts, alert distribution, and trend charts
- Advanced search across all security entities
- User management and role-based access (Admin / Analyst)
- Dark/light theme toggle and responsive UI

### Out of Scope
- Real-time agent-based log streaming (planned for Phase 2)
- SOAR (Security Orchestration & Automated Response) playbooks
- Native mobile application
- Integration with third-party threat intelligence feeds (Phase 2)

## 5. Methodology

The project follows an **Agile iterative development** methodology structured into four sprints:

### Sprint 1 — Foundation
- Requirements analysis and system design
- Django project scaffolding and database schema design
- Authentication, RBAC, and base UI layout
- Initial log parser prototype

### Sprint 2 — Core Security Engine
- Log parsing engine (multi-format support)
- Event classification and severity scoring algorithm
- Alert generation engine (rule-based correlation)
- Investigation module (case creation, status tracking)

### Sprint 3 — Intelligence & Visualization
- Dashboard with Chart.js visualizations (event trends, alert distribution, attack type breakdown)
- AI investigation assistant (OpenAI API integration for recommended actions)
- Advanced search across events, alerts, and investigations
- Settings and log file import interface

### Sprint 4 — Hardening & Polish
- User management and admin panel
- Theme system (dark/light mode with localStorage persistence)
- Sidebar UX improvements (collapsible/retractable)
- Accessibility review, responsive design, and final bug fixes
- Documentation, testing, and deployment preparation

### Development Philosophy
- **Backend First**: Model and API logic is built before templates
- **Security by Default**: Authentication required on all views; CSRF protection on all state-modifying endpoints
- **Separation of Concerns**: Log parsing, alert generation, and AI logic are isolated in dedicated modules

## 6. Technology Stack

| Layer | Technology | Justification |
|-------|-----------|---------------|
| **Backend Framework** | Django 4.x (Python) | Mature, batteries-included, excellent ORM and admin |
| **Database** | SQLite (dev) / PostgreSQL (prod) | File-based for rapid development, relational for production |
| **Frontend** | Django Templates + Vanilla CSS + JavaScript | No build tooling overhead; full control over markup |
| **Charting** | Chart.js | Lightweight, well-documented, no React dependency |
| **Mapping** | Leaflet.js | Open-source interactive maps for geolocating events |
| **Icons** | Phosphor Icons | Modern, consistent icon set with multiple weights |
| **Typography** | Inter + JetBrains Mono (Google Fonts) | Professional readability; monospace for log/metric data |
| **AI Integration** | OpenAI API (GPT-4o) | Accessible, high-quality NLP for investigation suggestions |
| **Authentication** | Django built-in auth | Session-based, secure, minimal configuration |
| **Deployment** | Gunicorn + Nginx | Standard Python WSGI stack |

## 9. Risk Assessment

| Risk | Probability | Impact | Mitigation |
|------|-------------|--------|-----------|
| Log format variability breaking the parser | Medium | High | Use regex-based multi-pattern matching with graceful fallback |
| OpenAI API rate limits / cost overrun | Low | Medium | Implement caching; allow toggling AI off |
| SQLite performance at scale | Medium | Medium | Design schema to be PostgreSQL-ready from the start |
| UI complexity exceeding single-developer capacity | Medium | Medium | Use component-based CSS; rely on Django template inheritance |
